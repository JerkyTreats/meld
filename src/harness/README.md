# Harness Domain

The Harness is a development-time observation surface composed from product primitives. It owns session manifests and derived diagnostic views. It owns no semantic product truth.

## Runtime Fidelity

Every session boots through the product initialization route for its selected registrations. The default root is temporary. Reusing a product data root requires the explicit unsafe flag.

Stimuli enter through canonical Event append and public domain command ports. The Harness does not write stores directly, manufacture semantic records, force cursors, or drive work to make a stalled runtime appear healthy.

Time and work budgets are injected. A sealed session records stimuli, step schedule, and closing positions so another reader can replay the same evidence.

## Observation

The served loopback contract and CLI fallback expose published contract values. External consumers remain non-authoritative and do not import product internals or open stores.

Live and playback handlers serve equivalent values from the same session evidence. Projections and walks derive from durable records and preserve their identities. Missing or out-of-scope records remain explicit rather than being converted into inferred truth.

Waiting-on declarations are observational products of domain selectors. They never gate, reorder, or fail semantic work. Their vocabulary remains domain-owned.

The Startup nonce account correlates the exact native preparation, generation, epoch, nonce, Curation, Plan, Task, Event, Graph, Belief and Agent positions. It names the first missing success-path position and keeps unresolved operational returns and publication obligations separate. Its two reads must agree on native positions, and a supplied inspection fence must match. A changed or historical fence cannot become a current success claim. The live Task Network reader shares the already opened native store and exposes no command submission.

## Durable Compatibility

Stored Harness records follow their actual encoding contract. A durable shape change preserves readable historical data through a bounded compatibility reader and characterization evidence. Compatibility does not create a second writer.

Reads are fenced to the active session unless a sealed playback mount explicitly selects retained history.

## Development Proof

Runtime corrections are demonstrated in a live Harness session before review when the changed behavior is observable through the Harness. The Harness observes the correction and never substitutes synthetic state for it.

Productization requests around the Harness remain outside the domain boundary. Consumers may render the published substrate, but consumer needs do not make presentation logic authoritative.
