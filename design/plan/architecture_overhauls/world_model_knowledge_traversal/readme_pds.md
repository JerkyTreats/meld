## Candidate outcome

Meld 3 must do at least one useful thing well: fully manage a serious README for Meld, with quality appropriate to its code and architecture. The production product is **README PDS**. `docs_freshness` remains a separate internal maintenance and harness PDS. A separate product does not by itself require a new semantic owner.

The user wants strong initial reasoning to remain useful over time. Begin with an excellent document, preserve its editorial intent and evidence relationships, and maintain it through the native runtime. Smaller models should be able to perform routine maintenance with the help of durable knowledge and CPU work. Occasional renewed strong-model judgment is compatible with this outcome. Reliable maintenance and the economic advantage are hypotheses to exercise, not established properties of a model tier.

The [root README](../../../../README.md) is the initial authored baseline for review. It distinguishes implemented mechanisms, demonstrated journeys and product ambitions. It is not yet a compiled README PDS product, an accepted native judgment or evidence of autonomous maintenance.

Acceptance means the document remains useful, accurate, coherent and recognizably itself through representative repository changes. The product must preserve its audience, explanatory structure, working examples and understated voice as well as factual correctness. Mere file existence, supported sentence counts, a successful write or native Goal satisfaction under the old freshness policy cannot establish this outcome.

Public command journeys should show initial assessment, a relevant change and bounded repair, a no-change revisit, and continuation after restart. They should retain the actual model contribution and reuse evidence needed to assess the claim of enduring intelligence. A damaged or flattened document must not pass simply because its remaining claims are supported. These are outcome checks, not a fixed implementation inventory or prescribed benchmark count.

## Why the current core can plausibly hold

The existing loop already separates installed theory, Agent intention, semantic observation, causal planning, authorization, execution and independent Goal judgment. A stronger README definition can follow those same transitions. Authoring richer product theory need not add another planner or teach Execution what makes prose good.

[PDS design](../../../cognitive_architecture/persistent_domain_stewardship.md) explicitly permits semantic resources and satisfaction contracts. [Docs semantic theory](../../../../owners/docs/src/docs/semantics.rs) already retains natural-language instructions for source extraction, README judgment, correspondence, drafting and revision, plus structured response formats. These fields are included in policy and generation identity. A quality standard can contain rich language without adding a corresponding primitive to [meld-lang](../../../cognitive_architecture/meld-lang/README.md).

An Astra-authored standard can therefore be installed product material when authorized by the product principal and admitted through owner contracts. Its authoring model does not become a new runtime authority. Generated prose is not automatically policy: the existing Docs path correctly treats source text and README text as data. Turning an exemplar into editorial instructions requires explicit authored material and admission.

The crucial distinction is between carrying a standard and implementing a meaningful judgment of it. Existing string fields can express editorial intent. They do not automatically extend the maintained condition or establish editorial acceptance.

## What the WAD analogy buys us

The useful interpretation of `meld-struct` is an identifiable body of installed product material that the engine can operate. Keep the name provisional. Current packages, compilation receipts, assignments and native stores already provide much of its physical role.

[Product compilation](../../../../src/theory/product.rs) currently binds exact package receipts and owner revisions. It validates composition; it does not infer an editorial maintenance model from arbitrary Markdown. There is no demonstrated README-to-product compiler in the inspected path.

A proposed README compilation would preserve the document itself alongside an explicit editorial brief, selected obligations, their evidence dependencies and the judgments required when they change. The result must retain information that cannot be reconstructed from the final prose alone. Why a section exists, who needs it and which tradeoffs the author made are part of the valuable initial reasoning.

Immutable selected theory and evolving knowledge remain distinct. The installed product supplies the definition and resources; activation and native stores retain observations, judgments and progress. A portable bundle or snapshot can refer to those records without creating another authoritative state store. An Agent is the maintained intention bound to this material, not the container for every document byte and record.

## Joy as editorial intent

The user's phrase, “joy is a property of alignment,” is an editorial hypothesis. Preserve it as part of the brief, with the document as an exemplar. Its observable expression can be reader confidence, a welcoming explanation, useful examples and quiet satisfaction when behavior follows intent. It need not become a keyword requirement, an adjective count or an invented joy score.

CPU work can preserve an unchanged approved passage, check dependencies and maintain the lifecycle of its judgment. When a repair changes the passage's meaning or its place in the document, assessing its voice still requires semantic judgment. A smaller model's ability to make that assessment remains an empirical question. Exact bytes and valid JSON cannot prove aesthetic success.

The initial author should leave the original wording and editorial rationale available to maintenance. Extracting only factual atoms would discard much of the intelligence this proposal intends to preserve. Neither repeated full rewrites nor freezing prose while facts drift satisfies the outcome.
