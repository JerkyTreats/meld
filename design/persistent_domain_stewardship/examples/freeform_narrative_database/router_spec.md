# Freeform Narrative Database Router Spec

Date: 2026-08-18
Status: discovery router exercise aligned to canonical PDS boundary
Scope: candidate PDS lowering for narrative database stewardship after the database baseline exists

## Purpose

This exercise separates the external narrative database contract from the optional PDS stewardship package. `theory::router` installs state-free stewardship meaning. It does not install a database schema, open an external endpoint, ingest a story, or make narrative products current.

The route map is illustrative. Graph projection registration, source-domain admission, event hydration, and semantic publication closure remain unresolved owner contracts rather than settled router routes.

No route component contains current documents, passages, graph facts, entity candidates, accepted claims, scene selections, or render requests. Installation stays inert.

## Database Baseline Outside Router Installation

Before stewardship activation, the external product and Meld need served contracts for:

```text
append exact producer products
replay producer products
materialize registered graph projections
query bounded graph and current selections
hydrate a graph fact to its authoritative event
recover exact source evidence
publish one complete semantic revision in bounded batches
```

These are domain and product integration contracts. They are not a PDS package body and are not owned by `theory::router`.

A future graph-owned projection-theory route may be useful, but this exercise records it only as an unresolved bridge. Adding it requires the graph owner to publish a state-free install and exact-resolution contract.

## Owner Semantics And Cross Links

The external narrative integration owner validates producer identity, product schema, source scope, editorial status, and exact source coordinates. Events own durable append and replay. Graph owns generic materialization, anchors, traversal, and provenance indexes. Belief owns the selected stewardship questions. Agent and execution own normative decision and action lifecycle.

```text
external producer product
→ served ingress and narrative admission
→ canonical event
→ graph projection and exact hydration
→ evidence mapping
→ belief and maintained-condition state
→ bounded maintenance action
→ external editorial or refresh result
→ narrative owner admission
→ verification evidence
```

The linker must reject a refresh method that lacks a current-source selector, affected-projection policy, exact capability, authority class, or outcome mapping. It must reject an evidence mapping that treats extraction confidence as editorial acceptance.

## Assignment And Activation

One assignment binds one exact package receipt to one principal, corpus subject, perspective, branch, requested authority, and principal grant. The external product endpoint and credentials belong to activation, not package identity.

Distinct assignments may maintain a private editorial branch, a shared canon branch, or different projection profiles over the same immutable source records. They retain separate current state, grants, capability catalogs, and source subscriptions.

Activation may bind a served Meld endpoint, external narrative endpoint, source watcher, extractor, graph query client, and render-spec generator. Preparation closes exact subscriptions and invokers without opening admission. Current publication waits for authenticated source identity, bounded query and hydration access, callback correlation, and every required adapter readiness receipt.

## Capability And Authority Closure

Candidate exact capabilities include:

```text
narrative.publish_revision
narrative.query_graph
narrative.hydrate_event_and_source
narrative.inspect_identity_candidates
narrative.propose_editorial_change
narrative.compute_affected_projections
narrative.refresh_scene_specification
narrative.verify_scene_specification
```

Some contracts belong to the database integration baseline and may be invoked without Agent stewardship. A PDS Strategy may select them for observation and maintenance only after exact installation and activation closure.

Query authority does not grant editorial mutation. Extraction authority does not grant claim acceptance. Refresh authority does not grant image generation or source rewriting. The external product remains the effective authority for its owned editorial products.

## Observation And Result Admission

External source advances arrive through passive delivery lineage:

```text
assignment subscription
+ activation generation
+ authenticated producer and adapter
+ source revision
+ publication batch and semantic revision identity
+ delivery cursor
```

Invoked reads, extraction, reconciliation, and refresh carry an exact capability ref, durable operation key, attempt id, generation, corpus, branch, and source revision.

Narrative admission checks exact producer ownership, source scope, complete semantic-revision closure, evidence coordinates, viewpoint, polarity, temporal bounds, editorial state, and operation or passive-delivery lineage. Incomplete publication batches remain non-current.

The visual system's success response proves only that an external operation completed. Narrative admission separately validates the returned render-ready specification and later outcome evidence. Image quality does not establish narrative claim truth.

## Isolation And Lifecycle Pressure

This case pressures service and state isolation because the external product may be long-lived, maintain its own cursors, and process several corpora. Each assignment subscription, source cursor, editorial branch, and callback must remain separately attributable.

A shared remote producer or local index may be allowed if it preserves tenant namespace, source revision, fairness, and authenticated delivery. It may not share principal grants or current projection state. Direct private-store access fails the isolation model even when both processes run on one host.

An interrupted multi-batch publication resumes under the same semantic revision identity and idempotency contract. It does not expose a partial revision as current. A callback from a retired generation remains stale or historical according to owner policy.

Historical interpretation replay uses admitted events and exact source lineage without requiring the external product to be online. Re-running extraction or scene generation is live new work.

## Interaction With Other Stewards

A lore steward may maintain identity and canon judgments over the database products. A roleplay steward may consume only admitted projections appropriate to one character perspective. The database steward does not absorb either mandate merely because it supplies their evidence.

The visual product is a peer capability and consumer. Its appearance memory and render history remain outside Meld unless later supplied as explicit evidence through a domain-owned adapter.

Several assignments may target the same corpus. Editorial effect arbitration remains with the external narrative owner and execution contracts, never the router.

## Router Falsification Findings

The router design is weakened or falsified for this case if:

- package installation opens the source database or processes narrative content
- the router owns source schema, graph projection, editorial acceptance, or render semantics
- an external client must read Meld storage directly
- partial publication becomes visible as a complete semantic revision
- graph proximity or extraction score is promoted directly to canon truth
- a shared service hides assignment, branch, source revision, or delivery lineage
- historical replay depends on the current external endpoint
- PDS is required merely to append and query narrative products

The case preserves the router boundary only by keeping the database substrate and PDS stewardship layer separate. The strongest unresolved bridge sits below PDS installation: generic source-domain projection and exact served hydration.

## Theory Set Implications

### Common Candidate Mechanism

- exact package, assignment, activation, and source lineage
- passive source delivery distinct from capability invocation
- selective observation over bounded projections
- maintained conditions and later outcome verification
- assignment-local capability and authority closure
- generation-fenced admission from persistent external services
- historical interpretation without live external dependencies

### Owner Specific Meaning

- narrative producer product schema
- source coordinates and semantic revision closure
- editorial acceptance and current selection
- narrative viewpoint, scope, polarity, and valid time
- qualified participation and scene projection
- render-ready narrative specification meaning

These products remain owned by the external narrative integration and graph domains. They are not universal PDS fields.

### Unresolved Bridge

- generic graph projection registration for new source domains
- served graph, anchor, provenance, and event-hydration reads
- bounded publication protocol for one semantic narrative revision
- boundary between external editorial decisions and Meld beliefs
- exact current-selection ownership for narrative projections
- outcome evidence for verified derived-scene refresh
