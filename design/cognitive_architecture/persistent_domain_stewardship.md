# Persistent Domain Stewardship

Persistent Domain Stewardship is Meld's productization domain. It expresses a durable software persona through owner-issued Domain Theory and binds that theory to Agents through assignment and activation.

World Model Reconciliation is runtime cognition. PDS is the declarative product material that gives that cognition purpose, scope, semantic resources, and standing responsibility.

## Product Model

A PDS product declares principals, directives, theory packages, package owners, assignments, activation conditions, required participants, and governance identity.

A product such as an Endless Horizon software developer may assign standing directives for dependency currency, documentation freshness, comment style, and test thoroughness. Product domains retain the meaning and verification contracts for those concerns.

## Theory Packages

A package is an immutable owner-issued unit of Domain Theory. It may contain directives, semantic schemas, comparator policies, graph publication contracts, Strategy knowledge, Curation templates, Capability references, satisfaction contracts, and presentation metadata.

A package never overrides the authority of the domain whose contract it references. Installation proves package integrity and owner admission, not truth of every proposition inside it.

## Assignment And Genesis

An assignment binds exact package revisions and principal declarations to an Agent identity. Activation realizes that assignment as one generation with an exact participant plan and durable receipt.

Agent genesis receives the directive set, perspective, owner routes, semantic resources, and activation identity derived from that assignment. After genesis, Agent, Strategy, Curation, Traversal, Belief, product domains, Events, and Execution perform the live reconciliation loop through their native contracts.

## Boundary With Reconciliation

PDS answers who the Agent is, what standing outcomes matter, which theory applies, and which owners participate. World Model Reconciliation answers what the Agent currently believes, what mismatch matters now, what Plan reconciles it, and how that Plan progresses.

PDS does not become a graph store, belief engine, Strategy runtime, Curation worker, execution scheduler, or Task Network.

## Activation

Activation binds one exact package receipt, assignment, Agent genesis, participant plan, owner readiness closure, runtime generation, and publication fence. A generation becomes current only when every required owner has published a durable readiness receipt for the same identity.

Retirement fences new work, drains owned effects, records safe points, closes cursors, and publishes one durable retirement result.
