# Goals And Methods

A Goal expresses a desired state with identity, authority, subject, target proposition, priority, lineage, and lifecycle. It does not prescribe how the state becomes true.

A Goal may remain world-model-local before any executable work exists. Execution receives Goal attribution only with a complete Task admission.

A Method is reusable declarative decomposition knowledge. It contains parameters, applicability conditions, a composition template, expected effects, provenance, and revision.

Strategy may instantiate Methods while constructing a Plan. A Method is a candidate generator rather than authority. Strategy owns semantic applicability, Agent owns authorization, and Execution never searches Methods to complete an incomplete Task.

The language provides Goal and Method values plus pure binding and validation. It owns no Goal lifecycle store, Method registry, ranking, or execution behavior.
