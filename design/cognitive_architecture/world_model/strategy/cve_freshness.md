# Dependency Security Strategy

Dependency security demonstrates that the same reconciliation architecture supports a different semantic domain without prescribing a fixed security workflow.

A standing directive requires governed software to remain adequately assessed against authoritative vulnerability knowledge. Dependency Security owns inventory, advisory, applicability, reachability, severity, mitigation, and verification meaning.

## Epistemic Ground

Curation may connect governed subjects to expected dependency inventories, inventories to component observations, components to advisory claims, and assessments to the evidence they require. Traversal exposes the relevant topology while preserving source and qualification.

Owner observations and belief settlement distinguish missing inventory, stale advisory knowledge, conflicting applicability, confirmed exposure, attempted mitigation, and verified resolution.

## Strategy Plan

A Plan may require an Epistemic Operation to establish missing assessment relationships, a complete Task to collect inventory or refresh advisory data, a complete mitigation Task, later observation, or a causal chain combining them.

A scan exit status is not an applicability verdict. A mitigation attempt is not proof that exposure ended. The Plan therefore represents the path from intended change to owner-issued observation and admitted satisfaction evidence.

## Authority

Strategy constructs the semantic response. Agent authorizes it. Curation authors epistemic structure. Execution realizes complete Tasks. Dependency Security owns admission and verification of its products. Agent owns Goal progression and satisfaction judgment under the assigned directive.
